
# JS: Конструкция `switch`

## 📌 Что это

`switch` заменяет **несколько `if`** — сравнивает выражение с несколькими вариантами. Читается нагляднее, чем длинная цепочка `else if`.

---

## 🔧 Синтаксис

```js
switch (x) {
    case 'value1':
        // ...
        break;
    case 'value2':
        // ...
        break;
    default:
        // ...
        break;
}
```

**Как работает:**
1. `x` сравнивается **строго** (`===`) с `value1`.
2. Если совпало — выполняется код с этого `case` до ближайшего `break`.
3. Если ни один `case` не совпал — выполняется `default` (если есть).

⚠️ `default` **необязателен**. `case` может быть много.

---

## 📋 Пример

```js
let a = 2 + 2;   // a = 4

switch (a) {
    case 3:
        alert('Маловато');
        break;
    case 4:
        alert('В точку!');   // ← выполнится
        break;
    case 5:
        alert('Перебор');
        break;
    default:
        alert('Нет таких значений');
}
```

**Порядок:** `3` → нет, `4` → совпало → «В точку!» → `break` → выход.

---

## ⚠️ Что будет без `break`

**Если `break` нет — выполнение «проваливается»** в следующий `case`, игнорируя проверки.

```js
let a = 2 + 2;   // 4

switch (a) {
    case 3:
        alert('Маловато');
    case 4:
        alert('В точку!');     // ← начинается отсюда
    case 5:
        alert('Перебор');      // ← выполнится
    default:
        alert('Нет таких');
                              // ← и это тоже
}
```

**Все три алерта сработают:** «В точку!», «Перебор», «Нет таких».

⚠️ **Не забывай `break`**, если не хочешь «проваливаться».

---

## 🎯 Любое выражение в `case`

В `switch` и `case` можно использовать **любые выражения**:

```js
let a = "1";
let b = 0;

switch (+a) {          // +a = 1
    case b + 1:        // b + 1 = 1
        alert("Выполнится");
        break;
    default:
        alert("Не выполнится");
}
```

`case b + 1` — **вычисляется** и сравнивается с `+a`. Работает.

---

## 🔗 Группировка `case`

Несколько `case` могут выполнять **один и тот же код**:

```js
let a = 3;

switch (a) {
    case 4:
        alert('Правильно!');
        break;

    case 3:                  // ← группируем 3 и 5
    case 5:
        alert('Неправильно!');
        break;

    default:
        alert('Странно');
}
```

**Как это работает:** если `a === 3` → начинается с `case 3:` → проваливается в `case 5:` (нет `break`) → выполняется общий код.

⚠️ Это **побочный эффект** отсутствия `break` — используется сознательно для группировки.

---

## 🔒 Строгое сравнение `===`

`switch` использует **`===`**, а не `==`. Типы должны **совпадать**.

```js
let arg = prompt("Введите число?");   // возвращает СТРОКУ

switch (arg) {
    case '0':
    case '1':
        alert('Один или ноль');
        break;

    case '2':
        alert('Два');
        break;

    case 3:                       // ❌ МЁРТВЫЙ КОД
        alert('Никогда не выполнится!');
        break;

    default:
        alert('Неизвестное значение');
}
```

**Почему `case 3` мёртв:**
- `prompt` возвращает `"3"` (строка).
- `"3" === 3` → `false` (разные типы).
- Сработает `default`, а `case 3` — никогда.

⚠️ **Классическая ошибка.** Если ожидаешь число, преобразуй: `+arg` или `Number(arg)`.

---

## 📊 Сравнение: `switch` vs `if/else if`

| Критерий | `switch` | `if/else if` |
|----------|----------|---------------|
| Сравнение | **строгое** `===` | любое (`>`, `<`, `==`, ...) |
| Читаемость | ✅ Лучше при множестве значений | ⚠️ Хуже |
| Гибкость | ⚠️ Только равенство | ✅ Любые условия |
| Группировка | ✅ Через проваливание | ❌ Через `\|\|` |

**Когда `switch`:** проверка значения **на равенство** многим вариантам.
**Когда `if`:** сложные условия (`>`, `<`, `&&`, `||`).

---

## 🎯 Связь с пентестом

- **Мёртвый код `case 3`** — пример бага из-за типов. Такие баги в авторизации: `case 'admin'` не сработает, если сервер пришлёт `case 1`.
- **Проваливание без `break`** — в чужом коде можно найти уязвимость: разработчик забыл `break`, выполняется лишний код.
- **`switch` в роутерах** — часто используется для обработки URL. Если забыли `break` — можно попасть не в ту ветку.
- **`default` без `break`** — не ошибка, но если после него есть код — может выполниться.
- **Тип имеет значение** — при анализе кода всегда проверяй: `case '5'` и `case 5` — **разные** ветки.
