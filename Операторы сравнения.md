# JS: Операторы сравнения

## 📌 Что это

Операторы сравнения возвращают **логическое значение** (`true` или `false`).

```js
2 > 1       // true
2 == 1      // false
2 != 1      // true
```

Результат можно сохранить в переменную:
```js
let result = 5 > 4;
console.log(result);   // true
```

---

## 📋 Все операторы

| Оператор | Значение |
|----------|----------|
| `>` | больше |
| `<` | меньше |
| `>=` | больше или равно |
| `<=` | меньше или равно |
| `==` | нестрогое равенство (с преобразованием типов) |
| `===` | **строгое** равенство (без преобразования) |
| `!=` | нестрогое неравенство |
| `!==` | **строгое** неравенство |

⚠️ `a = b` — это **присваивание**, а не сравнение.

---

## 🔤 Сравнение строк

Строки сравниваются **посимвольно** по коду Unicode.

```js
'Я' > 'А'         // true
'Коты' > 'Кода'   // true (т > д)
'Сонный' > 'Сон'  // true (длиннее)
```

**Алгоритм:**
1. Сравниваются первые символы.
2. Если равны — вторые, и так далее.
3. Более длинная строка больше, если все предыдущие символы равны.

⚠️ **Регистр имеет значение:**
```js
'A' < 'a'   // true (строчные буквы имеют больший код)
```

---

## 🔀 Сравнение разных типов

При `>` `<` `>=` `<=` и `==` — **оба операнда приводятся к числу**.

```js
'2' > 1         // true ('2' → 2)
'01' == 1       // true ('01' → 1)
true == 1       // true (true → 1)
false == 0      // true (false → 0)
```

⚠️ **Забавный баг:**
```js
let a = 0;
let b = "0";

Boolean(a);   // false
Boolean(b);   // true

a == b;       // true (оба → 0)
```

---

## 🔒 Строгое сравнение `===`

Не преобразует типы. Если типы разные — сразу `false`.

```js
0 == false        // true  ⚠️
0 === false       // false ✅

'' == false       // true  ⚠️
'' === false      // false ✅

'1' === 1         // false (разные типы)
```

**Правило:** всегда используй `===` и `!==`, кроме случаев, когда **сознательно** нужно преобразование.

---

## 🕳️ Особые случаи: `null` и `undefined`

### Строгое `===`
```js
null === undefined   // false (разные типы)
null === null        // true
undefined === undefined   // true
```

### Нестрогое `==`
```js
null == undefined    // true  (специальное правило)
null == 0            // false (не равно ничему, кроме undefined)
undefined == 0       // false
```

### Математические `<` `>` `<=` `>=`
`null` → `0`, `undefined` → `NaN`.

```js
null > 0        // false
null == 0       // false
null >= 0       // true  ⚠️ странно, но так работает
```

**Почему:** `null >= 0` работает через числовое преобразование (`null` → `0`), а `null == 0` — через специальное правило (не преобразуется).

### `undefined` несравним
```js
undefined > 0    // false
undefined < 0    // false
undefined == 0   // false
```
Причина: `undefined` → `NaN`, а `NaN` всегда даёт `false` при любых сравнениях.

## 🎯 Связь с пентестом

- **`==` vs `===`** — классическая причина багов. Например, `if (token == 0)` может пропустить `token = ""` или `token = false`.
- **Сравнение с `null`/`undefined`** — часто используется в проверках авторизации: `if (user == null)` может вести себя неожиданно.
- **Приведение типов** — эксплуатируется в обходах валидации: сервер ожидает число, а получает строку `"0"`, которая проходит проверку `==`.
- **`"0" == false` → `true`** — известная ловушка, из-за которой могут проходить «пустые» токены.
- **Логика авторизации** — если проверка `if (role)` (без `===`), то `role = "0"` пройдёт как **truthy**, хотя выглядит как «нет доступа».

---

## 🛡️ Как избежать проблем

1. **Всегда используй `===` и `!==`** вместо `==` и `!=`.
2. **Осторожно сравнивай с `null`/`undefined`** — только через `===`.
3. **Не используй `>` `<` `>=` `<=`** с переменными, которые могут быть `null`/`undefined`.
4. **Добавляй отдельные проверки** для `null`/`undefined`, если переменная может их принимать.

```js
if (value === null || value === undefined) {
    // обработать отдельно
}
```
